## Why

관리자 초대는 로그인 허용 목록만 생성하고 SMTP를 호출하지 않아 초대받은 사용자가 안내 메일을 받지 못한다. 현재 SMTP 연결·인증은 정상이다. 사용자가 초대 메일 미전송을 보고해 해당 동작을 보완한다.

## What Changes

- 새 초대를 생성하는 명시적 관리자 동작에서 초대 이메일을 한 번 발송한다.
- 기존 초대는 자동 발송하지 않고 관리자가 메일 보내기를 선택한다.
- 초대 등록과 SMTP 발송 상태를 분리하고 실패 시 원본 초대는 유지한다.
- 관리자 화면에 미발송/발송 중/접수 완료/실패, 접수 시각, 안전한 오류 및 수동 재전송을 표시한다.
- 취소·수락된 초대에는 발송하지 않고 중복 요청은 발송 attempt revision으로 차단한다.

## Capabilities

### New Capabilities

- `invitation-email`: 관리자 초대 안내 메일과 상태·수동 재전송.

### Modified Capabilities

없음. 기존 초대 기능의 추가 capability로 관리한다.

## Impact

초대 테이블 additive migration, 관리자 API/화면, 기존 SMTP transport 재사용. SMTP 인증 및 사용자 생성/로그인 권한은 변경하지 않는다. 자동 과거 발송·자동 실패 재시도·테스트 실제 수신자 발송을 하지 않는다.
